# Localization

[English](I18N.md) | [简体中文](zh-CN/I18N.md)

Cloud uses the same offline localization runtime and catalogs as HolePunch. English (`en`) is the default; Simplified Chinese (`zh-CN`) is supported through visible language selectors before and after login. Preferences persist per browser. Switching language must preserve the current route, unsaved forms, open dialogs, accessibility labels, and user-entered data.

The authoritative sources are `web/locales/en.json` and `web/locales/zh-CN.json` in the HolePunch repository. Read the [shared localization guide](../vendor/holepunch/docs/I18N.md) before changing messages. Edit those source files upstream, then run:

```sh
python3 scripts/sync-i18n.py
python3 scripts/sync-i18n.py --check
node --test tests/i18n.test.cjs
```

Publish the shared commit, update Cloud's pinned submodule, and validate here:

```sh
python3 vendor/holepunch/scripts/sync-i18n.py --check
node --test vendor/holepunch/tests/i18n.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Cloud's deployment tests check that browser-visible server diagnostics have shared catalog entries. Keep API fields, CLI commands, raw logs, resource names, and email addresses language independent. API diagnostics and transactional emails currently use English; localized email delivery is not implemented. Adding a browser locale requires complete keys/placeholders and selector support in the shared runtime and desktop app before it is advertised.

Verify administrator and member navigation, policy forms, invitations, password reset, setup, validation errors, mobile layout, and draft preservation in both locales. Never commit screenshots containing credentials or real tenant data.

## Documentation translations

`README.md` is the English project homepage; `README-zh.md` is its Simplified Chinese counterpart. Other translated guides live in `docs/zh-CN/`, with links back to English and the Chinese index. English remains the canonical reference; the Apache license text is distributed unchanged.

Keep examples, commands, API paths, environment variables, and code comments identical to the English source. Translate the surrounding explanations, headings, and tables. Update both languages together when behavior changes. Each translation records its repository-relative source path and SHA-256 content revision in a `translation-source` HTML comment. After reviewing the translated content, update that digest with `sha256sum SOURCE` (Linux) or `shasum -a 256 SOURCE` (macOS). The repository hygiene check rejects stale source revisions; changing only the digest is not a translation update.
